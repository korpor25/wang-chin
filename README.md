# ระบบสนับสนุนการผสมเทียมโคขุน — สหกรณ์การเกษตรวังชิ้น จำกัด

เว็บแอปสำหรับงานภาคสนามด้านการผสมเทียมและสุขภาพโค บันทึกได้แม้ไม่มีสัญญาณ
แล้วส่งขึ้นระบบให้เองเมื่อกลับเข้าพื้นที่ที่มีเน็ต

**ขอบเขตปัจจุบัน: เฟส 1 — กิจกรรมภาค ก (ก-01 ถึง ก-11) เท่านั้น**
ภาค ข คลังและทรัพย์สิน · ภาค ค รายงาน · ภาค ง ทบทวน ยกไปเฟสถัดไป
ยกเว้นสองอย่างที่ภาค ก ขาดไม่ได้ คือคลังน้ำเชื้อแบบอ่านอย่างเดียว (ก-08 ต้องเลือกล็อต)
และหน้าตั้งค่าพารามิเตอร์ชีววิทยา (ทั้งระบบคำนวณกำหนดการจากค่าชุดนั้น)

รายละเอียดข้อกำหนดทั้งหมดอยู่ใน [REQUIREMENTS.md](REQUIREMENTS.md)

## Stack

Vite + React 19 + TypeScript · react-router · Dexie (IndexedDB) · Zustand
`vite-plugin-pwa` (Workbox) · `@google/model-viewer` (โหลดเฉพาะตอนเปิดดูโมเดล 3 มิติ)

## คำสั่ง

```bash
pnpm dev         # dev server (service worker เปิดใช้งานด้วย)
pnpm build       # tsc -b && vite build
pnpm preview     # เสิร์ฟ dist/ พร้อมเปิด LAN
pnpm typecheck   # tsc --noEmit
pnpm lint        # oxlint
```

## หลักการที่ยึด

**ออฟไลน์ก่อนเสมอ** — ทุกการบันทึกลงเครื่องทันทีแล้วเข้าคิว ผู้ใช้ไม่เคยต้องรอเน็ต
งานภาคสนามเกิดในคอกที่สัญญาณไม่ถึง การออกแบบจึงเริ่มจากตรงนั้น ไม่ใช่จาก API

**ระบบคิดกำหนดการเอง** — บันทึกหนึ่งครั้งไม่ได้แค่เก็บลงตาราง แต่เปลี่ยนสถานะโค
ตัดสต๊อก และสร้างงานของรอบถัดไปให้อัตโนมัติ (`data/effects.ts`)
คนไม่ต้องจำเองว่าคลอดแล้วอีกกี่วันต้องตรวจมดลูก

**ค่าชีววิทยาปรับได้ ไม่ hard-code** — ทุกตัวเลขที่ใช้คำนวณอยู่ใน `BioParams`
ปรับผ่านหน้าตั้งค่าได้ เพราะที่ประชุมต้องปรับแล้วเทียบผลก่อน/หลัง

**ฟอร์มทุกตัวมาจากไฟล์เดียว** — `activities.ts` เก็บกิจกรรมเป็น data
(ใครทำ เมื่อไหร่ กรอกอะไร ระบบเอาไปคำนวณอะไรต่อ) แล้ว `ActivityForm` เรนเดอร์ตามสเปกนั้น
เพิ่มกิจกรรม = เพิ่ม entry ไม่ต้องเขียนหน้าจอใหม่ · เปิดภาคอื่นในเฟสถัดไป = แก้ `PHASE_GROUPS`

**ดีไซน์เปลี่ยนที่โทเคนที่เดียว** — สี ระยะห่าง มุมโค้ง ขนาดตัวอักษร อยู่ใน `:root` ของ `index.css`
ไฟล์ .tsx ไม่มีค่าคงที่ของสไตล์ฝังอยู่ (เหลือเฉพาะค่าที่คำนวณสด เช่น ความสูงแท่งกราฟ)

## โครงสร้าง

```
src/
├── domain/                # ตรรกะธุรกิจล้วน ไม่แตะ UI หรือฐานข้อมูล
│   ├── types.ts           # Role, Animal, ActivityRecord, Task, Alert, BioParams, ...
│   ├── rules.ts           # กฎกำหนดการ, golden period, breeding blockers, เกณฑ์สีน้ำเชื้อ
│   ├── activities.ts      # แคตตาล็อกกิจกรรม + ขอบเขตของเฟส (PHASE_GROUPS)
│   └── bcs.ts             # สเกล BCS 9 ระดับ กลุ่มคะแนน และคำแนะนำอัตโนมัติ
├── data/                  # ชั้นข้อมูล — IndexedDB ล้วน ไม่แตะเครือข่าย
│   ├── db.ts              # Dexie schema + ตัวนับ + audit log
│   ├── queries.ts         # คิวรีที่หน้าจอใช้ร่วมกัน
│   ├── effects.ts         # ผลข้างเคียงของการบันทึก → สร้างงานรอบถัดไป + แจ้งเตือน
│   ├── tasks.ts           # มอบหมายงาน ยกระดับงานค้าง และประกาศกิจกรรมสหกรณ์
│   ├── sync.ts            # outbox queue, retry/backoff, conflict, retention
│   └── seed.ts            # ข้อมูลตัวอย่างสำหรับ dev
├── routes/                # หนึ่งไฟล์ต่อหนึ่งหน้า
├── components/            # AppShell, ActivityForm, CowModel, ui.tsx (ชิ้นส่วนพื้นฐาน)
├── state/session.ts       # บัญชีที่กำลังใช้งาน
├── lib/                   # format (ตัวเลข/เวลาไทย), storage (โควตา/persist), image (บีบอัดรูป)
├── index.css              # โทเคนของดีไซน์ + ชิ้นส่วนพื้นฐาน
├── app.css                # สไตล์ของหน้าจอจริง
└── fonts.css              # @font-face ของฟอนต์ที่เก็บไว้ในโปรเจกต์เอง

public/                    # ไฟล์ที่เสิร์ฟตรง
├── fonts/                 # IBM Plex Sans Thai + Mono (117 KB) — ไม่ดึงจาก CDN เพื่อให้ออฟไลน์ได้
├── models/cow.glb         # โมเดล 3 มิติในหน้าโครายตัว โหลดเฉพาะตอนกดดู
└── *.png, favicon.ico     # ไอคอนทุกขนาด สร้างจาก assets/brand/logo.png

assets/brand/logo.png      # โลโก้ต้นฉบับ ใช้สร้างไอคอนชุดใหม่เมื่อโลโก้เปลี่ยน
```

## สามบทบาท เห็นคนละอย่าง

| บทบาท | ทำอะไรได้ | แท็บกลาง |
|---|---|---|
| เกษตรกร | ก-01 แจ้งคลอด · ก-07 แจ้งเป็นสัด · ก-11 เตรียมคอกคลอด | บันทึก |
| สัตวบาล | ก-01 ถึง ก-10 | บันทึก |
| เจ้าหน้าที่สหกรณ์ | ไม่มีกิจกรรมภาค ก — หน้าที่คือมอบหมายและติดตาม | มอบหมาย |

การกันสิทธิ์ทำที่ระดับ route ไม่ใช่แค่ซ่อนเมนู — พิมพ์ URL ของกิจกรรมบทบาทอื่นเข้ามาก็เปิดไม่ได้
**เมื่อต่อ backend จริงต้องตรวจสิทธิ์ซ้ำฝั่งเซิร์ฟเวอร์เสมอ** เพราะฝั่ง UI กันได้แค่ความผิดพลาด ไม่ได้กันเจตนา

## สิ่งที่ยังไม่ได้ต่อของจริง

| ส่วน | สถานะ |
|---|---|
| **Backend** | ต่อสายไว้แล้ว — ตั้ง `VITE_API_URL` (ดู `.env.example`) แล้ว `pushOne()` จะยิงจริง (409 = ขัดแย้ง) ถ้าไม่ตั้งจะใช้ตัวจำลองที่สุ่ม 8% error / 3% conflict ไว้ทดสอบ UX ทุกเส้นทาง |
| **Auth** | `state/session.ts` hard-code บัญชีไว้ใน array เลือกได้จากหน้าเข้าสู่ระบบ — ยังไม่สรุปว่าจะใช้ OTP หรือไม่ |
| **ข้อมูลจริง** | ทะเบียนฟาร์ม โค และน้ำเชื้อยังเป็นชุดตัวอย่าง รอไฟล์ Excel ชุดจริง |

## ข้อจำกัดของ PWA ที่ออกแบบเผื่อไว้แล้ว

วัดจริงบน Android (Chrome, RAM 4 GB, ติดตั้งเป็นแอปแล้ว) ก่อนเริ่มเขียนระบบนี้ ได้โควตา 14.5 GB
และ `persisted: true` — พื้นที่ไม่ใช่ข้อจำกัด แต่มีสองเรื่องที่มีผลกับโค้ดโดยตรง

- **นับ `syncStatus` ด้วย `count()` ไม่ได้** — โตแบบ O(n) (500,000 แถว = 5.1 วินาที)
  เพราะทุกแถวมีค่า index เดียวกัน index จึงช่วยอะไรไม่ได้
  → ตาราง `counters` เก็บยอดไว้ตรง ๆ แล้วบวกลบตอนเข้า-ออกคิวแทน
- **เหตุผลที่ลบข้อมูลเก่าไม่ใช่พื้นที่ไม่พอ** (โควตา 13 GB เทียบกับ 5 MB/ปี)
  แต่เพราะยิ่งค้างในเครื่องนานยิ่งเสี่ยงหายไปพร้อมเครื่อง และเสี่ยงข้อมูลรั่วถ้าเครื่องหาย
  → `pruneOldData()` ลบเฉพาะที่ซิงค์แล้วและเก่ากว่านโยบาย

**ชุดไฟล์ที่แคชไว้ใช้ออฟไลน์มี 827 KB** — ตัวแสดงผล 3 มิติ (1 MB) และไฟล์โมเดล (2 MB)
ไม่ถูกนับรวม จะโหลดเฉพาะตอนผู้ใช้กดดู แล้วเก็บแคชไว้ใช้ครั้งต่อไปได้แม้ไม่มีสัญญาณ

ต้องเสิร์ฟผ่าน **HTTPS หรือ localhost** เท่านั้น — Service Worker และการติดตั้ง PWA
ไม่ทำงานบน `http://` ที่เป็น IP ในวง LAN
